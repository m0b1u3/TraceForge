# 运行取消、执行权与硬截止

本批仅为通用底座，不增加场景动作或放宽沙箱权限。停止等待不等于证明外部动作没有发生。

## 控制链

`Run/Work 状态事件 → Embedded Worker 执行权核对 → LeaseWorker AbortSignal → 模型 / Gateway → Provider / Execution Node`

- 取消、暂停、Scope 撤销产生的 Run 事件同步核对当前 Worker 的 Run/Work/lease/worker 身份；失去执行权就取消本地执行。
- Worker 另以默认 1 秒间隔查询当前 assignment，每次查询也有 1 秒上限。租约过期、身份变化、查询失败或超时均停止执行。
  这是有界轮询而非实时远端推送；不新增后台续租，长工具调用仍须在有效租约内完成。
- Supervisor 关闭时取消活跃执行；重复执行同一 Worker lease 被拒绝。其他 Run 的状态事件不取消当前 Work。
- 模型、目录等待和本地观察器支持中断等待；模型信号独立于序列化请求，不能写进快照或 RPC JSON。
  即使替身忽略信号，迟到模型结果也不再驱动控制流。持久化待执行动作期间被取消，不能继续发出工具调用。
- Gateway 在目录、审批和派发边界检查信号；工具调用仍通过原来的执行权账本与授权策略。
  一旦进入执行阶段，取消/超时/异常必须先记 `uncertain`，不把它保存成成功回执，也不采纳迟到成功结果。
  用户取消状态和未知调用围栏分别持久化，重启不重派旧动作；未获独立证据不能自动清除围栏。

模型原有排队取消、受控 Provider 的公平调度取消、进程工具的终止请求及迟到启动清理被这条链复用。
不把任意第三方工具“不理会 AbortSignal”解释为真实进程已停止；其占用/不确定状态可继续保留，关闭会明确报未确认。

## 工具发现与关闭

`ExecutionToolDiscoverySource.discover(signal?)` 默认总等待 15 秒，可通过 Runtime 构造参数配置 1–300,000 ms。
超时取消该次发现，关闭该 generation 的准入，保存 degraded 元数据；迟到目录不发布，也不自动再次发现这个已排空的 generation。
尚未结束的发现仍计入来源在途数量，不能借超时伪造排空。替代版本发现失败不排空原活动版本；候选来源进入待清理集合。

deactivate/close 的排空和清理等待也有同样上限，超时报未确认而非删除来源或伪造清理成功。
相同已排空 source 对象不能作为成功重新激活；须显式管理流程处理旧 generation 并建立新实例。
Work 取消仅停止它等待共享发现，不强行取消其他 Work 仍可能需要的共同目录发现；后者由自身截止、排空或宿主关闭治理。

这里的硬截止覆盖外部 `discover()` 和排空/关闭，不宣称任意自定义持久化 statePort 的 load/save 也被抢占；
生产 SQLite 状态端口仍按原事务失败处理。持久化写入不能简单丢弃 Promise 后继续更新状态。

## RPC 与 Provider

- `ExecutionNodeRpcClient` 每次调用（含连接等待）默认 120 秒截止，上限 300 秒；不自动重发。
  超时移除本地响应关联，迟到响应忽略，错误明确远端结果未确认。默认最多 256 个在途调用，上限 4096，
  写缓冲限制为两倍单帧上限。连接 generation 阻止旧连接关闭/迟到建立破坏新连接的请求。
- Execution Node Provider 总请求截止覆盖握手、进程启动、发送和响应，不只覆盖 tools.call 响应阶段。
  使用原 requestTimeoutMs（默认 15 秒）；调用取消会请求停止，关闭后不静默恢复，必须显式 restart/恢复。
- 取消发生在握手期间，迟到握手不能再启动进程；已请求启动而结果未确认时保留错误状态。
  若迟到启动返回可用进程归属，则请求清理该进程，不能再发送 Provider 工具命令。
- 清理请求及后续终态观察总计最多等待 min(5 秒, requestTimeoutMs)；终止请求先返回 running 时继续观察而不是直接报告完成。
  失败或启动结果未知时，普通 Provider 和 MCP 都保留 failed，
  close/restart 报错，不能把清理失败藏成 stopped。进程描述符的终态仍不是独立的进程树/外部副作用证明。
- 原开发子进程客户端也接收取消并结束进程；测试实际启动中性 Node Provider，不代表 Windows 沙箱验收。

RPC 截止只结束 Host 等待，不远程回滚已派发动作；没有返回进程句柄的启动超时，仍须已有持久化执行账本/进程历史和独立证据恢复。
Provider 信号不会越过序列化边界作为授权传给远端，也不授予远端新增 Host 能力。

调度边界：Managed Provider 的本地公平调度名额在调用清理路径结束后释放，但后续占用批次已在释放前保留外部 retained 名额。
生产默认 Managed Provider factory 根据持久化账本恢复这些占用；active 计数仍不能证明外部进程退出，须看 occupied/retained。
普通终态观察也不自动释放外部名额；独立证明通过授权核验后才释放。自定义来源、内置进程工具及其他 MCP 来源尚未统一接线，
详见 `execution-capacity.md`。这里的配额保护不代替平台可信清理签发或 Invocation 恢复授权。

## 回归与剩余边界

回归包括 HTTP 取消/暂停/Scope 撤销、非协作模型与工具的迟到结果、未知调用跨宿主重启、Worker 租约/身份/查询超时、
待执行检查点期间取消、真实 Provider 子进程终止、非协作发现/启动/清理，以及真实本地 Socket RPC 的截止与容量。
既有 Execution Node 进程工具测试覆盖输入/输出等待与迟到启动取消。

真实模型、多日长跑、Windows 双模式及独立清理证明仍未验收。任意第三方实现若忽略取消，底座只能拒绝后续动作、
请求清理并报告未确认，不能承诺操作系统一定已终止它。以上状态不解除 Invocation 恢复围栏。
后续审计批次已补齐共享事件 decoder、有归属的断点游标、压缩/恢复事实补记和模型取消终态的结构化持久化，
见 `agent-audit-replay.md`。事件表示取消请求、观察或独立对账，仍不能代替进程清理证明；永久账本扩容未交付。
