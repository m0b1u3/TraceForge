# 失信包下的 Run 取证、停止与退役

2026-09-01。单用户底座管理能力，不增加应用 UI、具体安全场景、账号或租户系统。

## 为什么单独提供处置入口

正常 Run 加载和执行必须检查当前场景包信任。包缺失、文件被替换、审核过期或被撤销时，这条执行路径应继续拒绝，不能为了查看或停止旧任务而把包重新放行。
`ScenarioRunDisposalControl` 因此不持有 Registry、Definition 或场景策略：只读取通用事件与执行账本，提供固定的 `stop` / `retire` 操作，没有任意命令、恢复执行、换包或重试工具入口。

`readRunForensics` 使用 Core 的纯事件归约函数恢复历史状态，不调用输出解码、授权策略、工厂或模型。它核对事件起点、数量/序号、Run/Case、版本绑定、修订号和状态投影。
这里的完整性检查不是整条历史的密码学来源证明；拥有数据库修改权限的宿主仍在信任边界内。原记录缺损或投影不一致时拒绝控制，不猜测并修补历史。

普通 `DurableScenarioRuntime.execute` 同时收紧为提交前验证当前及目标状态的包可用性，包括新 Run；不再先追加事件再由返回时的加载报失信错误。
取证得到状态不代表已获执行授权，不能拿它作为正常 Runtime 绕过包信任的替代入口。

## 状态和语义

| 处置诊断 | 含义 |
| --- | --- |
| `stop_required` | Run 尚未结束；可申请独立授权的停止 |
| `stopped_unresolved` | Run 已取消/完成，但调用、占用或模型等还有未收尾记录 |
| `ready_to_retire` | Run 已结束，当前列举的账本没有待处理项；仍需独立退役授权 |
| `retired` | 已持久化退役回执，当前没有已知待处理项；历史不删除 |
| `retired_unresolved` | 已有退役回执，但当前又出现未核实记录；回执不掩盖迟到异常 |

停止在一个 SQLite 事务内追加通用 `run_cancelled` 事件与不可变处置审计，复用既有投影：取消未结束 Work，撤销当前租约，取消待批记录，并关闭尚处于 prepared 的调用绑定。
原审批决定、输出、证据引用、检查点正文及此前事件不改写。关闭执行权不等于某个外部动作从未启动，既有 executing/uncertain 结果和进程占用仍保留。
已取消或已完成的 Run 再申请 stop 可记录本次授权审计，但不会伪造新的取消事件或把已完成 Run 改成取消。

提交后发出变更通知：Embedded Worker 的所有权核对改为只读通用事实，不因包失信而跳过取消；既有 Model Runtime 收到取消事件后取消该 Run 的在途/排队模型请求。
Worker 通道、租约、派发授权和 Run 终态共同阻止新动作。迟到的工具结果不会因停止而自动变成有效回执；不合作的远端动作仍需要独立核实。
通知不参与数据库事务，也不是清理证明；重复请求可再次发出通知，进程重启依赖持久化终态与已有未知执行恢复，而非内存通知。

退役只允许 cancelled/completed Run，并在授权结束后的同一事务内检查：活动租约、待批、prepared/执行中/未知调用、缺执行状态的未完成绑定、未释放的进程/Managed 占用、在途模型调用与 queued/admitted 模型准入。
占用恢复表未初始化时拒绝，不能当成零占用。即便某个进程记录为 terminal_observed，也须经既有独立清理核验才算 released。
检查通过只写一次退役回执，不删除 Run、不释放配额、不签发清理证明，也不修改包撤销或原 scope。
已经未知的调用结果继续通过既有调用对账/可信证明处理；进程通过既有独立清理入口处理。处置接口不具备给这些事实背书的权限。

## 管理接口与授权

生产 Foundation 默认注册以下入口，均受既有管理能力通道保护；匿名与 Worker 通道不可使用。

- `GET /api/scenarios/runs/:runId/disposal?caseId=…`：历史 Run 状态、当前阻塞类别/数量/最多 20 个示例身份、退役回执。标记 `forensic_only` / `executionAuthorized=false`。
- `GET …/disposal/events?caseId=…&after=0&limit=20`：按事件 sequence 的 keyset 分页，保留原事件和命令身份，不通过包解码。
- `GET …/disposal/records?caseId=…&kind=…&after=0&limit=20`：检查点、审批、调用、进程或 Managed 占用的身份/状态/引用分页。kind 为 `checkpoints / approvals / invocations / processes / managed`。
- `POST …/disposal`：caseId、operation（stop/retire）、commandId、expectedRevision、actor、reason。
- `GET …/disposal/audit?caseId=…&commandId=…`：核验并回读本次处置审计及关联的取消事件。

可信宿主提供 `SecurityAgentFoundationOptions.runDisposalAuthorizer.authorize(request)`；缺配置默认拒绝。
授权输入是固定请求与只读取证状态的副本；允许结果须含非空 authorizationRef 和未来 expiresAt，异步等待最多 10 秒。
actor 只是本人操作标签，不是授权凭据。即使包和 scope 均已失效，独立处置授权也只能停止/退役，不能借此执行原任务。

授权后复检请求修订和完整状态摘要，发现任务变化则冲突，需重新读取再提交。当前阻塞项在退役事务中重新查询，不信任预检时的占用快照。
同 commandId 同请求每次仍须重新授权，幂等回读原审计；不同正文冲突。审计与取消事件原子提交，不存在只有取消或只有成功审计的半次操作。
退役回执按 Run 唯一。回读核对审计摘要、身份、操作及取消事件引用；历史表禁止更新/删除。

## 恢复路径和保留边界

- 临时材料损坏：可以先取证；恢复原审核字节后正常信任校验仍独立生效。如果已执行 stop，终态不会因材料恢复而自动续跑。
- 永久撤销或包缺失：无需再次加载旧包即可取证、停止和核对占用。退役不撤销包的撤销事实，不自动升级或改绑旧任务。
- 新版本任务：须另行安装审核、创建适用授权和任务；原证据与审批不能被暗中改写成新执行的依据。
- 已存在的兼容 Run/策略迁移依然要求相关版本当前受信，不把处置通道扩展成不受检迁移器。

事件/记录分页不需要完整回放，即使投影异常仍可按宿主管理权限读取原事件。记录页仅返回身份/状态/引用，不返回原始工具输出或完整检查点正文；归档正文仍通过已有带完整性校验的存储接口读取。
取消会改变活动状态投影，但不会删掉历史审批、检查点或输出；“退役”是保留记录的处置完成标记，不是删除数据。

## 有界性、故障验证与剩余工作

- 后续 [运行快照与事件归档](scenario-event-history.md) 已接通取证/控制读取：总历史可分段保存，单次最多归约 5,000 条/16 MiB 尾部事件，状态仍限 2 MiB。超限拒绝，不宣称任意大小状态可处置。
- 事件/记录页默认 20、最多 100 条；对外事件页最多 4 MiB，底层单段冷热读取最多解码 16 MiB。超大单事件仍需受控处理，不以截断伪装完整事实。
- stop 最多更新合计 1,024 条租约/待批/准备中绑定投影；在写前按数量做保守 recovery 物理余量准入。超限拒绝整个操作，不部分取消。
- 处置审计全库最多 50,000 条、单项 8 KiB，使用 recovery 物理余量；满额拒绝，不删除历史腾空间。同步回放/数据库操作不能由异步授权截止抢占。
- 本批 39 项新增集成回归包括无包/撤销包取证、提交前信任拒绝、历史保留、独立授权/竞态/幂等、未知占用、模型阻塞、字节/写入上限、路由保护及真实在途工具取消。
  停止事件写入、停止审计写入、停止提交后、退役审计写入、退役提交后五个窗口真实 SIGKILL，各使用两次新宿主回读。

后续 Run 事件历史批次已提供有界快照与冷热回读，正常 Runtime 和处置不再依赖一次反序列化全部旧事件；仍核验压缩段完整性，不删除证据链或放宽当前包信任。
真实模型、24/72 小时长稳、任意 JS 沙箱、Windows 双模式实机以及实际远端强制终止仍未因此验收。
