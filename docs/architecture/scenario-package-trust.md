# Scenario 包审核材料与当前使用门禁

2026-09-01。面向单用户安全智能体底座；不增加具体安全场景、账号、租户、上传执行器或应用 UI。

## 校验的对象与边界

包版本号不能证明磁盘文件或内存代码仍是审核时的内容。本批增加两个不同的条件，缺一不可：

1. **可验证材料**：清单固定精确包绑定、入口及声明的依赖/数据文件，记录文件路径、用途、字节数和 SHA-256。Ed25519 审核签名覆盖材料摘要、声明契约摘要、宿主装配引用、审核引用、签发者和有效期。
2. **可信宿主关联**：宿主以同步 `assertAssembly(package, review)` 明确确认，当前已装配对象对应这份独立审核材料。底座同时捕获并复检工厂、授权策略、输出校验/映射的函数引用和声明契约。

第二项不是自动证明。底座不会根据路径 import 代码，不比较 `Function.toString`，也不能从文件签名推导内存对象的来源。无条件放行的宿主回调不构成代码来源证明。
包顶层代码可能在宿主导入时已经执行；闭包内部状态、清单外动态依赖、对象返回的任意实现和同进程 JS 私自调用系统能力不受这项校验隔离。
材料读取是有界的逐文件复检，不是原子文件系统快照，也不是抵御控制宿主文件系统的攻击者的 OS 沙箱。发行审核必须独立确认依赖完整性，并约束材料目录的写入者。

## 宿主配置与旧包迁入

`SecurityAgentFoundationOptions.scenarioPackageTrust` 接受：

- `installations`：宿主显式安装的材料根目录、manifest 和 review。根目录须为 `realpath` 返回的真实绝对路径，不接受符号链接别名；没有 HTTP 上传或路径安装入口。
- `authority(keyId)`：每次使用时解析当前审核公钥、允许的包 ID、有效区间和撤销状态。只接受 Ed25519；审核有效期必须落在签发者授权期内。
- `assertAssembly(package, review)`：上述可信宿主关联验证；未提供、拒绝或错误返回 Promise 都阻止使用。
- `revokeAuthorizer.authorize(request)`：独立的撤销授权，默认拒绝；允许结果须有非空授权引用和未来有效期，异步等待最多 10 秒。
- `allowUnreviewedDevelopmentPackages`：仅供显式开发/测试装配；诊断为 `development_unreviewed`。已持久化登记的版本或提供了无效审核的版本不能用此选项降级绕过验证。

迁入现有包时，应先独立审核发行目录及完整依赖，生成清单和签名，再由可信宿主确认当前装配对象与审核材料的关系并传入配置。
系统不自动为历史包生成签名，不因“当前只安装这一版”而背书旧代码。审核私钥不进入模型、工具或运行时校验配置；运行时仅需受信公钥。
同 id/version 首次登记后，绑定、材料和声明契约不可替换。原材料可以获得新的合法审核签名；代码或声明变化应使用新版本。

生产 Foundation 默认隔离无审核材料的包，零场景宿主仍可启动并提供健康检查、定义元数据和受保护诊断。
现有 `main.ts` 的 Web 装配也默认隔离，提前构造的 Execution Node 授权不会持有绕过门禁的裸 Registry。
当前应用入口没有发行审核配置或 UI 适配；要运行包须由受信宿主显式完成上述组合，不能把开发开关设成生产默认。Web 场景开发继续冻结。
SDK 裸 Registry 仍是低层宿主/测试契约，并非自带生产信任体系；生产组合使用受检 Registry。

## 当前使用与失信后的行为

受检 Registry 在精确包解析时重新检查审核、当前公钥信任、有效期、持久化完整性、本地字节、声明和函数引用及宿主关联。
固定 scope 的 Action/Resource 授权、Run 加载/恢复、授权兼容升级、Run 迁移和上下文选择均使用这一门禁，不因过去成功过就继续放行。

场景来源装配跳过隔离包，不调用其工具工厂。已装配来源在 discovery 前后以及旧目录里的工具实际执行前再次检查，撤销后不能靠旧目录继续调用。
隔离包的工厂不执行，因而不能枚举它的来源名：有隔离包时未匹配的宿主来源 policy 暂留为未使用配置，不发放执行端口；全包可用时仍拒绝未知 policy。
上下文目录跳过隔离包，避免一个失信包令其他包的目录整体失败；实际读取仍受固定 scope 和既有资源生命周期约束。

材料缺失、替换、签名失效或撤销返回 `recovery_required`，不自动换包、迁移、重试工具或删除原事件、审批、检查点和证据。
正常装配后发生文件损坏，恢复原审核字节可再次校验；启动时审核配置无效的包保持本次宿主隔离，修正配置后需重新装配/启动。
撤销是针对不可变材料的永久事实，不因重启、重新签发同一材料或开发开关而恢复信任。

后续 [无包依赖 Run 处置](scenario-run-disposal.md) 已提供独立管理入口，在不调用旧包的前提下读取历史、安全停止、核对占用并授权退役。
正常 Run 加载/命令仍拒绝失信包；处置不是恢复执行。未知调用和占用继续保留，须由既有独立核验流程处理；超大历史的流式处置仍未实现。

## 管理、审计与持久化

以下入口由既有管理能力通道保护，匿名和 Worker 通道不能操作：

- `GET /api/scenarios/package-trust`：当前可用性、原因、审核/材料引用；不返回材料根路径、公钥或签名私钥。
- `POST /api/scenarios/package-trust/revoke`：`commandId`、精确 `package`、`actor`、`reason`；`actor` 只是本人操作标签，不是授权依据。
- `GET /api/scenarios/package-trust/revocations?commandId=…`：回读不可变撤销审计并校验摘要。

撤销固定请求快照，独立授权后事务内复检有效期；撤销与审计一次提交。同 commandId 同请求仍须重新授权后幂等回读，不同请求冲突。
没有自动恢复或解除撤销接口。它阻止后续受控使用，不保证终止已经派发的外部动作，不释放尚未核实的进程占用，也不制造清理证明。
材料和审核首次登记同样事务提交；失败、物理余量不足或强杀都不能留下半次登记。历史表禁止更新/删除，满额拒绝新增。

边界上限：单次配置最多 256 个包；单包最多 128 个文件、单文件 1 MiB、聚合 4 MiB，遍历最多 256 项/16 层；逐项目录读取，不把任意大目录先整体载入内存。
材料历史最多 256 条/单项 64 KiB，审核历史最多 1,024 条/单项 16 KiB，撤销最多 10,000 条/单项 4 KiB；新增使用既有物理存储 recovery 余量准入并计入保守写入开销。
不提供历史分区、无限扩容、安装/替换文件的原子发布或自动排空；每次使用全材料复检有同步 I/O 成本，大规模性能验收尚未完成。
10 秒等待截止不能抢占同步恶意 JS 或同步文件系统阻塞。

## 验证口径

中性 fixture 覆盖签名/有效期/公钥、材料替换/缺失/链接、声明及函数替换、当前授权和 Run 恢复、旧工具目录撤销、生产管理路由、持久化原子性和容量拒绝。
登记事务中、撤销事务中、撤销提交后三个窗口真实 SIGKILL，各用两次新宿主回读。fixture 的装配关联是测试宿主显式确认，不伪装成自动代码加载验证。
没有调用真实模型，没有运行用户暂缓的 24/72 小时长测，也没有验收任意 JS 沙箱或具体安全场景。
