# 受控上下文资源包的签名离线迁移

本批迁移的是已有 Package 契约下完整的上下文资源集合，不是安装 Scenario 可执行代码、授权策略或迁移脚本。
生产宿主通过 `SecurityAgentFoundationOptions.contextPackageTransfer` 注入管理授权、签名者和信任根，默认全部关闭。
HTTP 和模型工具不是同一入口：模型没有导入、导出或信任根管理能力。

## 范围与内容

`traceforge.context-package.v1` 是一个有界 JSON Envelope，采用 Ed25519 对规范化 payload 签名。
它包含 keyId、Package id/version/schemaRevision、签发时间、位置无关的 manifest 摘要、按 ID 排序的完整资源清单与签名。

- 支持清单全部由上下文资源组成的 Package：Skill 文本/结构化契约、知识文本、包内引用/冲突关系、授权动作、角色/阶段/能力要求与有效期。
- 每个本地资源带正文，按资源声明的 SHA-256 精确校验；缺项、重复、额外字段、修改契约、不同清单 revision 均拒绝。
- 外部 MCP Resources/Prompts 只带已审核的资源声明和 profile 摘要，正文必须为 null。即使源宿主缓存过远端正文，也不会作为离线内容搬走。
  目标端必须已有相同 source/profileDigest 的受控配置，导入仅核对依赖，不联网、不启动进程。
- 不携带宿主环境变量、私钥、进程命令/配置、实际 resource locator、授权批准或运行态。位置无关摘要故意不包含本机 locator；导入不解释文件路径或解压文件。
  正文及既有 MCP 资源参数仍是用户提供的数据，可能含敏感信息；导出授权者负责审查内容，不能宣称自动检测或删除所有嵌入秘密。
- 含非 context 资源（如可执行资产、migration）的混合清单整体拒绝，不偷偷导出一部分再称完整包。

目标宿主必须预先安装完全匹配的资源契约；导入不注册新 Definition，不改变授权策略，不选“最新版本”，不改旧 Run 的固定绑定。
Host 的授权函数与 Scenario 代码仍通过原来的可信部署方式安装。不同 MCP 部署配置导致 profile 摘要变化时，须独立审核并更新声明/版本，不能由导入绕过。

## 管理接口

`POST /api/scenarios/context-packages/transfer`，JSON 公共字段为 commandId、actor、reason、action、package。

| action | 额外输入 | 结果与副作用 |
| --- | --- | --- |
| export | 无 | 当前授权、生命周期与完整性检查后签名；保存不可变归档与审计，返回 archive |
| import | archive | 验签、精确清单/依赖/生命周期核对后原子发布正文、导入绑定、归档与审计；不返回正文 |
| inspect | targetCommandId | 独立授权后读取指定 Package 的命令元数据；不验活资料、不写入、不重试，不返回归档正文 |

结果带 archiveDigest、`context-transfer:<commandId>` 审计引用、`executionAuthorized: false` 和 `automaticRetryAllowed: false`。
inspect 即该引用的受控解析入口；全局资源管理事实不虚构 Case/Run 或发布为工具执行事件。
授权端口得到操作、操作者、理由、Package 和导入/审计的 archiveDigest，不接收签名私钥或正文。
没有授权器、拒绝、异常、过期均不发布；授权等待上限 10 秒，迟到 grant 不得继续执行。输入在等待授权前固定为独立 JSON 快照，
调用方随后修改对象不能改变获授权的归档摘要、Package 或命令。最终提交前再次检查授权期限与签名者状态。
管理端口是可信宿主依赖；actor 文本本身不代替部署 API 身份认证或授权器的身份验证。

## 原子性、重放和信任

解析后的 Envelope 留在有界内存隔离区，全部验证通过才进入同一 SQLite 事务；没有磁盘 staging 或 zip 解压目录。
正文安装、签名原件、Package→archive 固定绑定与授权审计一起提交。中途失败/强杀仅留下未发布的回滚状态；提交后可直接恢复读取。
发布不依赖另一个文件系统 rename，因而不需要半包修复或后台重试进程。

同 commandId 同请求的导入幂等；不同请求冲突。导出重放返回同一个签名原件，但仍重新授权、核对当前正文与生命周期。
成功导入后的重放也重新授权、验签和读取已安装正文；资料丢失、损坏、退役或撤销时拒绝，不借重放重新安装。
同 Package 版本固定一个签名归档摘要；即使内容相同，重新签发的另一个 Envelope 也不能静默覆盖。签名轮换/重新背书迁移尚需后续受控机制或新版本。

签名者必须是 Ed25519、被允许签发该 Package ID，签发时间位于信任有效期且不晚于当前时间，当前仍未过期/撤销。
签名 Base64 必须规范，清单和正文均在签名内。签名只证明来源和完整性，不把文本变为系统指令、证据或执行许可。

已导入资料的 `SqlitePackageContextStore` 在读取/选择时调用当前信任验证器；没有验证器也拒绝，不因重启变回“本地可信安装”。
默认生产装配与 Worker/Planner/Observer 的现有资源投影复用此检查；签名者撤销后，当前模型输入不再使用这些资料。
原 Receipt、快照和签名原件保留供审计。资源的当前 Scope、角色/阶段/能力、有效期和 MCP profile 仍由既有执行链独立校验。
目的地已有退役/撤销标记不能被导入清除；未导出的远端新撤销信息不能靠离线文件凭空得知，部署方仍需更新信任根与撤销配置。

## 容量与保留

- HTTP 整个请求及程序调用输入上限 1 MiB；单 Envelope 也不超过 1 MiB。导入应为公共命令字段预留大小。
- JSON 深度最多 32、节点最多 100,000；资源最多 1024，单本地正文最多 64 KiB；总内容还受既有 8 MiB/2048 条上下文库限制。
- 签名原件最多 128 个、合计 16 MiB，转移审计最多 2048 条；新写入检查物理执行余量。原件、导入绑定和成功命令审计不可覆写或删除。
- 满额/物理压力拒绝发布，事务回滚；没有自动删除历史腾空间。资源退役可以回收活动正文，但不会删除签名原件中的审计正文。
- 尚未交付原件冷热归档/扩容、多节点同步、全卷断电验收或大规模包读取性能基线。

## 验证

37 项回归覆盖：完整 Skill/知识包迁移、MCP 声明不带缓存、精确 Package/依赖/清单、签名/授权拒绝与授权期间请求不可变、
规范签名/结构/HTTP 容量、撤销/退役/过期、只读审计、并发幂等/版本冲突、磁盘压力、最终提交失败与信任/授权变化回滚。
三个真实 SIGKILL 断点覆盖归档已写但未提交、正文已写但未提交、整批已提交；每个都重新打开数据库两次，再验证授权重放。
生产 HTTP Host 回归验证导入后 Worker 能通过 Gateway 读取，签名者撤销后下一次模型输入过滤旧资料而保留原 Receipt。
模型为确定性测试适配器，不是真实模型验收；没有运行 24/72 小时长稳或 Windows 平台验收。完整基线见开发计划。
