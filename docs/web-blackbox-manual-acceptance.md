# 黑盒 Scenario 手动验收

本批不连接外部 CTF，不调用真实模型；自动回归使用受控本机夹具。手动验收面向 macOS Apple Silicon 桌面，不代表 Linux 验收或正式安装包已完成。

## 准备

启动 `pnpm dev:desktop`，在模型设置确认可用模型。使用自建或明确允许自动化测试的可重置目标；记录目标、允许的方法/影响、停止条件和预期交付物。只授予需要的精确 URL 或经确认的 URL 前缀。需要身份时在宿主配置身份句柄，不把密码填入普通工具参数。

Scenario 0.5.1 的内容与运行文件已变化，并补齐上下文读取能力与资源授权。需要按既有签名/审核流程重新打包、安装并批准该版本；不要覆盖一个已审核的旧版本目录或修改摘要绕过信任检查。旧 Run 继续绑定其原版本，不自动迁移到新包。

### 客户端指导资源验收

在“设置 → 场景与扩展”选择已审核的场景，修改包内指导并新建自己的 Skill/角色指导/知识资料，选定其父资源、角色和阶段，保存配置。也可导入 UTF-8 Markdown/TXT；已有正文须确认替换，删除须再次确认。待确认期间保存和重新读取应不可用。

开始新任务后核对 context.catalog/read 的实际资源 ID、摘要和正文与保存修订一致；再修改或删除该资源，旧任务应仍读原内容，新任务使用新修订。父资源停用或撤销时，相应用户资源不能绕过读取边界。角色指导目前作为上下文资料，不替换系统提示词；导入不会执行 Markdown 中的脚本。MCP 新连接/凭证/发现测试界面尚未完成，不列作本轮通过项。

## 一次完整流程

1. 发起调查并确认范围。检查模型先识别目标和可用能力，而非擅自扩大授权。
2. 查看探索输出：链接可以进入有界队列，表单只显示方法、动作地址和字段名，不应自动提交，也不应泄露字段值。动态页面能力不足时应明确说明。
3. 提供或观察至少两个独立疑点。检查它们都成为独立假设，只有一个验证任务执行；进度能解释当前正在验证什么。
4. 让一次验证按请求预算暂停再继续。检查使用原候选/Work/计划，准备请求不重复，控制与候选观察都进入证据。
5. 在另一个独立测试 Run 中验证停止/断开情况。不要对有副作用的真实目标故意制造未知结果；可在可重置本地夹具模拟丢响应。未知效果应显示为阻塞，重启和写入 inconclusive 复核都不能自动重发。
6. 查看复核和报告：支持的候选不等于已验证漏洞；会话探索、遗漏、未完成候选和浏览器覆盖限制应保留。点击引用确认能找到真实证据。若用户目标是获得特定结果，需要有归属明确的证据，不能只根据页面宣称成功。

## 反馈格式

提供 Run ID、Scenario 版本、模型、失败阶段、相关工具名、预期行为、实际行为及证据引用。涉及凭据先脱敏。不要只发最终回答截图：保留最后一次成功操作、待确认操作和停止原因，才能区分场景策略、模型行为、工具能力与宿主问题。

## 尚不能据此宣称完成的能力

当前对照执行主要是一次性前置请求加重复 GET/HEAD；不等于任意多步利用、可交互浏览器登录、任意 CLI 工具、资产测绘或指纹识别全覆盖。报告构建器不会自动读取或推进 Finding 生命周期。真实模型调查效果和 macOS 桌面全流程以本次手动结果为准，不能拿夹具通过代替。
