## 本轮修复的实际问题

1. 去重指纹原来随 prompt 窗口截取，旧位置的工作结果/图节点变化可能不触发新评估。现在指纹覆盖本 Case/Run 的全部可见语义状态，prompt 仍按预算投影；继续忽略纯 lease/worker 所有权变化。跨 Case 图输入拒绝，外 Case 节点不进入上下文。
2. Observer 原来可能在模型返回后把并发新增状态一起推进为已读。Planner/Observer 现在在应用决策前检查共享语义状态，发生改变则保留旧评估为未应用并重新评估，不把旧答案当新状态的决策。
3. 压缩会保留早期图引用，但 Planner 验证曾只接受末尾窗口内的节点。现在引用验证针对 Case/Run 可见图，仍不接受越界身份，不把显示预算当授权规则。
4. 真实测试发现 Node ABI 恢复后 Electron rebuild 标记仍可能命中缓存。开发准备明确强制重建 SQLite，避免标记与实际二进制不一致；这是开发环境修复，不是新增发布系统。

以上都不包含攻击技术、具体目标、供应商或状态码编排规则。
