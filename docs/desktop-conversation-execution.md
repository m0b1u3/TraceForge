# 桌面对话中的执行进展

## 2026-09-08 当前交互补齐（覆盖下方历史只读审批说明）

RunInteraction 从当前 Run 的 work.pendingApproval 展示审批卡，不从历史事件推断待处理命令。批准要求查看具体参数、勾选核对、填写理由；拒绝只要求明确理由。参数来自固定只读 approval-input 端点，宿主验证所属 checkpoint 与待执行 invocation，缺失/超限不批准。文本作为 inert JSON 渲染；完整日志和模型推理不传入 UI。

补充信息目标是已有工作项，作为 operator 来源 directive 保存，在当前 Run 的 directives 中可追溯，并通过原 worker/context 传递。它不会授予权限、恢复暂停或重试失败。审批/input 命令共用持久日志；显示对应运行和操作，核对原命令，不替换未知结果。旧合同/不可用 checkpoint 不伪造参数预览。

浏览器截图 output/playwright/interaction-desktop.png、interaction-narrow.png 是合成数据；真实 SQLite 测试覆盖批准/拒绝和核对回放，非真实模型端到端验收。

## Operate 表面方向合同

这是现有“行动谱面”桌面对话的接线增量。沿用 `DESIGN.md` 的白色阅读面、石板色文字、细分隔线和系统字体；用户消息居右，智能体进展居左。对话是阅读主线，工作项、来源引用和启动/停止控件按需展开。此文记录该表面的交互与数据合同，不重新定义全局视觉身份。

用户先保存调查说明，再展开“启动或停止任务”确认授权并执行。保存回执只表示本机会话已持久化。进展必须来自宿主保存的 Run 状态；界面不生成示例回复，也不将等待输出显示为模型正在流式回答。

## 数据关联与刷新

`apps/server/src/desktop-execution-routes.ts` 的 `GET /api/desktop/conversations/:conversationId/execution` 按会话所属 case 读取 Scenario 运行目录与状态，并从 `desktop_execution_commands` 中查找未被拒绝的运行绑定，将 `messageCommandId` 加到每个返回的 Run。缺失绑定时返回 `null`。路由同时返回 definitions、scopes、modelReady 和目录截断标记。

`apps/web/renderer/conversation-execution.tsx` 校验运行快照后，以保存消息的 `commandId` 与运行的 `messageCommandId` 精确匹配，在对应用户消息后投影智能体进展。关联不依赖消息文字相似度。没有绑定、或对应消息不在当前加载记录中的运行，显示在独立的“会话关联运行”区域，适用于旧运行与其他未绑定记录。

对话挂载时立即进行只读 GET；每次读取完成后，在可见文档中延迟 2 秒再读，隐藏文档中延迟 15 秒再读。这是定时读取已保存状态，不是事件订阅或模型 token 流。隐藏状态在安排下一次读取时检查；没有单独的恢复可见立即刷新监听。组件卸载时取消定时器并忽略迟到结果；HostWorkbench 按会话 ID 重新挂载该组件。

暂时读取失败或响应校验失败时保留上次有效快照，并显示更新失败提示与“重新读取状态”按钮；后续只读轮询仍继续。首次读取失败没有历史快照可显示。读取不会自动重试授权、启动或停止操作。

## 展示与操作

智能体进展显示 Run 状态、已保存输出摘要，以及按需展开的工作项标题、状态、运行目标、运行 ID 和版本。无输出时分别说明运行仍等待已保存输出或已经结束但没有保存输出。未知状态保留原值供识别。

每条输出的 `refs` 在“查看依据”中以引用文字列出，并提示引用不等于结论已验证。这是来源引用展示，不是完整 artifact 阅读器，也没有凭单条引用判定安全发现的逻辑。

对话底部的原生折叠区仅在打开时挂载既有 `ExecutionPanel`，关闭后卸载；这里的按需加载是组件挂载控制，并非动态模块导入。授权、启动和停止继续使用该面板的既有流程。左侧“任务”“证据”入口仍能打开独立面板，并提供返回对话入口。

`apps/web/renderer/host-workbench.tsx` 的输入框仍执行保存消息命令。打开会话、读取状态、保存消息均不会自动派发 Run。Run 生命周期、规划、授权语义和执行仍由现有 Scenario 接口承担，展示层不替代这些判断。

## 当前限制

2026-09-08 命令收口：授权、启动、停止共享严格请求 schema 与版本化 `desktopReceipt`。Renderer 的 ExecutionController 先写日志，再核对会话、命令、操作和资源身份；未知回执保持原命令，不能仅凭 HTTP 2xx 宣称成功。同存储的面板控制器共享 Renderer 内同步锁，服务器原 Run 身份/命令幂等继续承担持久防重。确认现在绑定消息、授权内容/期限和定义版本，范围变化不能沿用旧勾选。停止被接受不等于外部副作用已确认清理。

- 路由最多读取目录前 20 个 Run；超出时界面显示截断提示，没有运行分页。没有显示的运行不代表尚未执行。
- 对话是持久化 Run 的投影，尚不是完整模型对话流；不提供 token 流、自动派发、完整工具活动时间线或完整 artifact 阅读器。
- 快照读取依赖 definitions、scopes、运行目录及所选运行状态均读取成功；其中一项不可用会使本轮读取失败。
- 每个组件挂载期间保留最近成功快照；离开对话再返回会重新读取，并非跨挂载的快照缓存。
- 本文依据实现描述行为，不代表真实模型、原生沙箱、Electron 视觉或可发行桌面整链已经验收；能力状态与验证基线以 `docs/development-status-and-roadmap.md` 为准。
# 2026-09-08 增量执行记录补充

桌面对话中的 RunProgress 使用会话所属 Run 的固定只读事件端点，通过既有 Agent 协议读取进展、模型和工具生命周期、审批状态。整页验证连续序号与 Case/Run 归属后推进游标；失败保留已有记录，恢复只读取，不重新执行。每页 100，呈现最近 100；重新打开会话从持久事件重建，不将 UI 当状态真源。

RunControl 复用 ExecutionController、持久日志与严格回执，实现行内停止/原请求核对。审批事件只读，不提供伪批准按钮；桌面审批命令和补充信息仍待实现。事件记录不是内部推理，也不是逐 token 输出。工具依据沿用 EvidenceReference。合成截图位于 output/playwright/progress-desktop.png 与 progress-narrow.png，不代表真实目标验收。
