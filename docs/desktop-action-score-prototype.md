# 行动谱面：桌面精细原型

## 已确认，不再重选

用户以截图明确指定行动谱面布局，完成度对标精致的 Claude Desktop、ChatGPT 桌面应用。不是选择常规聊天产品方向，也不是把旧 Web 应用换皮。旧选择页是否提交成功不影响此确认。

保留：左侧窄导航、中央连续对话和底部输入、右侧按需打开的任务/证据、行动时间标记。去掉草图手绘质感、展示页的黑黄边框与 BACK/DETAILS 等按钮。原型不含其他产品品牌，不固定某种漏洞或 Web 目标。

## 同一方向的三个空间方案

| 稿件 | 布局重点 | 取舍 |
| --- | --- | --- |
| A 并列核查 | 对话、证据、最右行动时间轨分别排列，最接近用户选中草图 | 多项信息便于对照，但窄窗口需要折叠侧区 |
| B 合并侧栏 | 证据与时间标记合并为一个可收起侧区 | 对话更宽，行动标记与证据共用空间 |
| C 轻量旁注 | 证据像附属批注打开，时间标记压缩为对话边注 | 对话干扰最少，密集行动需要另行展开 |

用户回复 `a` 确认 A，仅实现这一套；随后明确要求用户消息居右、智能体回复居左，此要求覆盖 A 原稿的双侧左对齐。不是三套产品，不恢复旧前端，不重写底座调度。

## 场景与状态

示例为“整理现有观察 → 提出验证计划 → 点击来源 → 等待人工确认”。所有内容必须标记演示数据，未调用模型、不执行调查。证据为待验证观察，不是已确认 Finding；时间标记只代表示例中的过去活动，不预测未来耗时。

首次使用缺少模型或场景时，输入区展示真实缺口；运行时以状态回执驱动摘要；请求结果未知时保留待确认，不自动换 ID 重发。右区默认按需展开，收起后保留引用、草稿和滚动位置。审批是明确操作，不把聊天中的“可以”直接变成后端批准。

## 实现准备清单

- 新 renderer 使用语义化文字与真实控件重建，不能把整张原型图片当界面。
- 导航图标带可访问名称，展开区有关闭入口与焦点返回，中文输入法组合阶段不触发发送。
- 行动轨只能使用真实可用的起止时间；缺时间显示未知，不编造精确条长。
- 宿主会话/消息适配、事件投影、证据读取和恢复按 desktop-interaction-contract.md 接线；现有模型配置仍为宿主级。
- 验收按一条完整流程执行：模型配置、授权调查、对话进度、审批、引用核查、退出恢复；界面原型不计作这条链路完成。

## 当前交付口径

图像检查：A 最接近用户指定的原草图，作为推荐布局；B 将行动记录移到侧栏底部，C 的边注比提示词设想更宽，应以实际图像而非方案名称判断。B 的“操作记录（已完成）”不能在实现中用来描述等待确认，C 自动补充的日志名/日期/进程例子不是产品规则或真实证据；全部仅为图上演示内容，正式实现采用受控中性数据和真实状态。图中的候选标志不代表已确认品牌 Logo。

图片与提示词保存在 .impeccable/mocks/，A 已记录 approved:true，B/C 保留未采用状态。新源码位于 apps/web/renderer/，只复用现有 React/Vite 依赖，不复用已退役的旧 src、样式或 API 客户端。预览构建输出独立 renderer/dist，不是旧 web/dist。

已实现的预览与尚待接通的真实能力见 [预览说明](desktop-renderer-preview.md)。下一步是当前宿主的完整接线，不再重新选择设计：模型配置、授权调查、消息送达、执行事件、审批、证据引用和恢复。实际作用是让当前可点击的界面真正驱动调查，并可靠知道消息是否送达、操作是否执行、证据是否可核查。正式启动/打包围栏仍保持。
