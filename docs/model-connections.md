# 模型连接与验收边界

更新日期：2026-09-24。TraceForge 的模型连接由桌面设置、宿主凭据存储、供应商目录、协议适配与 Model Runtime 组成。正式工作台的设置入口可读取、测试和保存连接；保存影响后续模型调用，不修改已经固定的 Run 配置。Scenario 和 Core 不持有供应商账号常量。当前实现与优先级以[开发状态](development-status-and-roadmap.md)为准。

## 连接合同

- 供应商预设与协议类型分开；当前协议适配包括 Chat Completions、Messages 和 Responses。供应商/型号目录是可选元数据，列出型号不保证该账号能生成、调用工具或处理附件。
- API Key 和受管账号引用互斥。Secret 留在宿主安全存储，Renderer、配置导出、日志和模型消息只使用掩码或引用。端点变更不能隐式继承旧端点的凭据。
- 请求可配置思考模式、推理强度、温度与输出上限；不适用当前协议的字段不应偷偷发送。私有续接数据只可在同协议、型号、端点和账号绑定下继续，不显示为公开思考内容。
- 连接目标沿用受约束传输：HTTPS 或显式本机回环 HTTP；不在 URL 中放凭据，不跟随重定向到其他目标。受管账号发现、登录、刷新与退出要分别显示实际状态，不能把登录成功当作模型能力通过。
- 保存连接不触发模型生成。用户主动测试连接可能产生供应商费用；真实验收必须使用隔离配置，不覆盖日常模型设置。本仓库后续真实模型开发测试只使用 DeepSeek，首选 `deepseek-flash`。

## 当前不足

最近通过的真实模型验收是隔离 `deepseek-flash` 与本机中性网页的桌面浏览器交接。它不覆盖所有供应商、模型、协议参数、附件形式、长上下文和安全调查结论。具体缺口和每批实际回归数见[当前开发状态](development-status-and-roadmap.md)。
